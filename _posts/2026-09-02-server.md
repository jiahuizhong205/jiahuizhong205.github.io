这篇整理了我在大创项目 **SBFL-LLM-Framework** 实验里用到的常用命令，从 SSH 免密登录、查看服务器状态，到用 Docker 跑流水线、后台执行实验、排查问题，按流程串起来，方便以后查用。

## 一、SSH 免密登录

每次输密码登录太麻烦，把本机公钥推上去就能免密。

**Windows PowerShell：**

```powershell
type $env:USERPROFILE\.ssh\id_ed25519.pub | ssh root@101.132.23.129 "mkdir -p ~/.ssh && chmod 700 ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys"
```

**Linux / macOS：** 把 `type $env:USERPROFILE\...` 换成 `cat ~/.ssh/id_ed25519.pub`。

命令拆解：

| 片段 | 作用 |
| --- | --- |
| `type ...\id_ed25519.pub` | 读取本机 ed25519 公钥 |
| `\| ssh root@ip` | 通过管道把公钥传给远程服务器 |
| `mkdir -p ~/.ssh` | 不存在则创建 ssh 配置目录 |
| `chmod 700 ~/.ssh` | 设置 ssh 目录权限 |
| `cat >> ~/.ssh/authorized_keys` | 追加公钥到授权密钥文件 |
| `chmod 600 ~/.ssh/authorized_keys` | 密钥文件权限，ssh 强制要求 |

## 二、查看服务器状态（基础）

拿到一台服务器，先摸清它的状态：系统、CPU、内存、磁盘、进程、端口。

### 系统信息

```bash
uname -a                # 内核版本
cat /etc/os-release     # 发行版信息
uptime                  # 运行时长 + 平均负载（load average）
```

### CPU 与内存

```bash
nproc                   # CPU 核心数
lscpu                   # CPU 详细信息（型号、架构、缓存）
free -h                 # 内存使用情况（-h 人类可读）
top                     # 实时查看 CPU/内存占用 + 进程（按 q 退出）
htop                    # top 的增强版，彩色、可鼠标操作（需安装）
```

### 磁盘

```bash
df -h                   # 各分区磁盘使用率
du -sh 目录名           # 查看某个目录占多大空间
lsblk                   # 块设备与挂载关系
```

### 进程与端口

```bash
ps aux                  # 所有进程（CPU/内存占用、启动命令）
ps -ef | grep 关键词    # 按关键词找进程
ss -tlnp                # 查看监听的 TCP 端口（哪个程序占用哪个端口）
```

### Docker 资源

```bash
docker stats            # 各容器实时 CPU/内存/网络/磁盘 IO 占用
docker ps               # 正在运行的容器
docker images           # 本地镜像列表
docker inspect 容器ID   # 容器详细配置（挂载卷、网络、环境变量）
```

> `docker stats` 是排查「哪个容器吃内存」最常用的，配合 `free -h` 和 `top` 基本能定位大部分资源问题。

## 三、Docker 运行实验

### 启动 Docker 服务

重启服务器后 Docker 默认是停的，先启动：

```bash
systemctl start docker
```

### 前台运行流水线（调试用）

```bash
docker run --rm \
    -e LLM_API_KEY="sk-xxx" \
    -v "$(pwd)":/app \
    -v d4j_workspace:/app/d4j_workspace \
    sbfl-llm-env:latest \
    python3 run_pipeline.py
```

参数说明：

| 参数 | 作用 |
| --- | --- |
| `--rm` | 容器退出后自动删除，不残留 |
| `-e LLM_API_KEY="xxx"` | 注入环境变量，给 Python 读大模型 API 密钥 |
| `-v "$(pwd)":/app` | 绑定挂载，服务器当前目录映射到容器内 `/app`，代码实时同步 |
| `-v d4j_workspace:/app/d4j_workspace` | Docker 命名卷，实验数据持久化，容器销毁数据保留 |
| `sbfl-llm-env:latest` | 本地镜像名:标签 |
| `python3 run_pipeline.py` | 容器内执行的流水线脚本 |
| `\` | shell 续行符，多行排版用 |

### 容器内批量安装 Python 依赖

```bash
docker run --name pipfix -v "$(pwd)":/app sbfl-llm-env:latest \
pip3 install --no-cache-dir -r /app/requirements.txt -i https://mirrors.aliyun.com/pypi/simple/
```

- `--name pipfix`：给容器命名，便于管理
- `--no-cache-dir`：不使用 pip 缓存
- `-i` 阿里云镜像：国内加速 pip 下载

> ⚠️ 这种方式只是**在临时容器里装依赖，不会改镜像**；要固化依赖需要重新构建 Docker 镜像。
> 清理同名冲突容器：`docker rm pipfix`

### 后台运行实验（nohup + 内存限制）

```bash
cd /root/SBFL-LLM-Framework && nohup docker run --rm -m 3g \
    -e LLM_API_KEY="sk-xxx" \
    -v "$(pwd)":/app -v d4j_workspace:/app/d4j_workspace \
    sbfl-llm-env:latest python3 run_pipeline.py > experiment.log 2>&1 &
```

| 片段 | 作用 |
| --- | --- |
| `cd ... &&` | 切换项目目录，前面成功才执行后面 |
| `nohup` | 脱离 SSH 会话，关掉 ssh 窗口程序继续跑 |
| `-m 3g` | 限制容器最大内存 3GB，超出会 OOM 杀死（退出码 137） |
| `> experiment.log` | 标准输出写入日志 |
| `2>&1` | 错误输出也重定向到同一日志 |
| `&` | 放到后台执行，立刻返回提示符 |

> 🔐 安全提示：命令行直接写 API 密钥会留在 shell 的 `history` 里，建议用 shell 变量传入。

## 四、实验运维

### 容器与日志

```bash
docker ps                          # 查看正在运行的容器
docker ps -a                       # 查看所有容器（含已结束，可看 OOM 退出状态）
tail -f experiment.log             # 实时跟踪日志
```

### 停止实验

```bash
docker stop <容器ID>
```

> ⚠️ **不要 kill nohup 进程**——nohup 托管的只是 docker 客户端，真正计算在容器里，必须 `docker stop` 才能停。

### 数据卷管理

```bash
docker volume ls                  # 查看命名卷
docker volume rm d4j_workspace    # ⚠️ 删除命名卷 = 清空 d4j 全部实验数据
```

## 五、网络与加速

### GitHub 克隆代码国内加速

```bash
# 浅克隆，只拉最新 commit，速度快
git clone --depth=1 https://githubfast.com/用户名/仓库名.git

# 已有仓库改远程地址
git remote set-url origin https://githubfast.com/用户名/仓库名.git
git pull
```

- `--depth=1`：浅克隆，不下载完整 git 历史，适合大仓库
- `githubfast.com`：GitHub 国内加速镜像，**仅用于 clone/pull，不支持 push**

### 排查连通性

```bash
curl -I https://github.com    # 测试 GitHub 网络连通
ssh -T git@github.com         # 测试 ssh 到 GitHub 的连通（返回 Hi xxx 即成功）
```

## 六、踩坑总结

1. **Exited(137)**：容器内存超限被杀死，调大 `-m 3g` 为 `-m 4g`/`-m 5g`。（第一次四个并发真的把服务器跑崩了，我不行了，重启解决。。）
2. **nohup 只是托管 docker 客户端**：真正计算在容器里，杀 nohup 进程不会停实验，必须 `docker stop`。
3. **命名卷 `d4j_workspace` 独立于容器生命周期**：容器删除实验结果不会丢，`docker volume rm` 才会清空。
4. **正式后台跑实验前**，先前台不带 nohup 跑一遍，确认代码无报错。
5. **API 密钥不要硬编码在命令行**：优先用 shell 环境变量传入，防止密钥泄露（留在 history 或日志里）。
