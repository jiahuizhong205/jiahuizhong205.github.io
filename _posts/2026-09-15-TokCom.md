Token Communications: A Large Model-Driven  Framework for Cross-Modal Context-Aware  Semantic Communications

①面向语义信源压缩的 TokCom；②带语义信道编码的 TokCom；③语义多址接入 TokCom；④TokCom 网络协议。如fig3所展示；

## Figure 1：TokCom整体框架图｜跨模态上下文驱动生成式语义通信

![TokCom 整体收发框架](/assets/img/posts/2026-09-15-TokCom/fig1.png){: w="1240" }
_文本/图像/音频经各自 Tokenizer 化为 Token 序列，送入 GFM/MLLM 做跨模态融合；打叉方块是发送前「为压缩而掩码」的 Token。信道中部分 Token 丢失，接收端 MLLM 依靠跨模态注意力预测补全，再经 De-tokenizer 还原三种模态。_


### 图结构拆解
图分为左右两大模块：**Transmitter发射端**、**Receiver接收端**，中间是无线信道/网络。
1. **发射端**
    - 输入三类多模态原始数据：Text文本、Images图像、Audio音频。
    - 每一路数据送入独立`Tokenizer`，把原始信号转换成Token序列。
    - 全部模态Token送入`GFM/MLLMs`（生成式基础模型/多模态大模型）做跨模态融合处理。
    - 方框带叉符号：`Token masked for compression`，为了压缩，在发送前对部分Token做掩码丢弃。
2. **中间信道**
    信道会带来信道质量波动、用户意图信息；经过信道后部分Token丢失。
3. **接收端**
    - 收到受损的Token流，部分Token在传输中丢失（红色叉标记）。
    - `GFM/MLLMs`依靠**Cross-Modal Attention跨模态注意力**，利用其余留存Token的上下文，预测丢失的Token。
    - 恢复后的Token送入`De-tokenizer`反Token化，分别还原出文本、图像、音频原始输出。

### 核心表达含义
> 不再传输原始像素/音频采样点，而是传输多模态Token；收发共享大模型能力，**依靠跨模态上下文补全传输丢失的Token，避免重传**。

## Figure 2：Transformer的两种上下文学习与Token预测模式

![Transformer 的两种上下文预测模式](/assets/img/posts/2026-09-15-TokCom/fig2.png){: w="1240" }
_(a) 单向 Transformer 自回归预测下一个 Token，只利用历史上下文，对应发射端的信源压缩与自适应调制编码；(b) 双向 Transformer 做掩码建模，可同时读取前后 Token，对应接收端的丢包修复。_


### (a) Unidirectional Transformer 单向Transformer：下一个Token预测
- 工作逻辑：自回归模式，只能利用**当前位置之前历史Token**，预测后续Token的概率分布 $p(s_i | s_{<i})$。
- 流程：Token码本输出Token ID映射为Embedding嵌入向量；模型基于历史序列输出下一个Token概率；输出Token经过`De-tokenizer`还原原始内容。
- 典型代表：GPT系列。
- TokCom中的用途：发射端基于预测的下一个Token概率，做信源压缩、自适应调制编码。

### (b) Bidirectional Transformer 双向Transformer：掩码Token预测
- 工作逻辑：掩码建模，可同时访问**前后双向全部Token**，预测被`[MASK]`掩码隐藏的位置。
- 流程：输入带掩码的Token序列；自注意力同时读取前后Token信息提取嵌入；专门预测掩码位置的Token。
- 典型代表：BERT、MaskGIT。
- TokCom中的用途：接收端修复信道丢失/损坏的Token，是丢包恢复的核心能力。

> 两种模式各司其职：单向适合编码端预测，双向适合接收端掩码修复。

## Figure 3：TokCom四大基础应用架构总览

![TokCom 四大基础应用架构总览](/assets/img/posts/2026-09-15-TokCom/fig3.png){: w="1564" }
_四大基础架构：(a) 语义信源压缩——算术编码做无损压缩，或丢弃低重要性 Token 做有损压缩；(b) 语义信道编码——经 CLIP 语义对齐，把语义相近的 Token 映射到更近的星座点；(c) 语义多址接入——多用户 Token 非正交叠加，接收端按语义正交性分离；(d) 语义网络协议——Token 打包后经不可靠网络传输，接收端预测丢失包，仅对无法恢复的包重传。_


### (a) Semantic source compression 语义信源压缩
- **左侧-无损Token压缩**：多模态信号经过Tokenizer，MLLM输出Token概率，配合算术编码，实现无损压缩比特流。
- **右侧-有损Token压缩**：基于下游任务的重要性评估，直接丢弃不重要的Token；在语义层面完成有损压缩，服从率-失真-感知权衡。

### (b) Semantic channel coding 语义信道编码
将N维Token嵌入空间映射到M维数字调制星座空间。
> 核心规则：经过CLIP语义对齐，**余弦相似度高、语义接近的Token嵌入向量，映射到距离更近的星座点**。
> TokCom信道编码不只是看信道SNR，同时参考Token自身的语义可预测性。

### (c) Semantic multiple access 语义多址接入
- 场景：两个用户同时传输，Token在非正交多址接入时发生信号重叠、碰撞。
- 解决思路：不依靠传统正交资源，利用`GFM/MLLMs`，依托两路数据流各自的**上下文与语义正交性**，在Token域把两个用户信号分离开，对应论文ToDMA协议。

### (d) Semantic network protocols 语义网络协议
1. 发射端：把Token封装进数据包，主动丢包完成码率控制；数据包内携带强上下文信息。
2. 信道：不可靠网络，发生数据包丢失、出错。
3. 接收端：利用跨模态信息，调用MLLM直接预测丢失/出错包对应的Token ID，不需要请求重传全部包；只有完全无法恢复的包才触发重传。

## Q1：很多传统深度联合信源信道编码 DeepJSCC 语义通信方案需要端到端训练；TokCom 不需要端到端训练，具备良好可扩展性与任务自适应能力。这是什么意思？

**A：** 这两种技术代表了语义通信领域两种截然不同的思路。

**DeepJSCC 像一位"专家"**，为了特定任务需要从头学习。它的核心是让神经网络（编码器和解码器）作为一个完整系统工作，直接把原始数据映射成适合信道传输的信号，并在接收端还原。这套系统的"智能"完全来自编码器和解码器之间的默契配合，而这种默契只有通过端到端训练才能建立。后果是模型与特定任务、数据分布、信道条件深度绑定，一旦场景改变，往往需要重新训练，可扩展性和自适应能力较弱。

**TokCom 像一位"通才"**，直接调用已经学成的"大师"（大模型），因此无需自己从头学起。它把通信的基本单位变成"语义令牌（Token）"——这正是当前各种大模型的原生输入输出格式。TokCom 不再自己构建端到端编解码系统，而是直接利用预训练好的大模型来处理语义令牌：发送端用大模型把信息变成令牌，接收端用大模型把令牌还原成信息。通信系统本身不负责"理解"语义，只负责高效可靠地传输令牌。

带来的好处：

- **可扩展性**：复用通用大模型，可轻松处理文本、图像、音视频等不同模态
- **任务自适应**：同一个预训练模型可服务不同下游任务，无需为每个任务重新训练通信系统

## Q2：模型训练最小化对数似然损失，等价于隐式优化压缩性能。这句是什么意思？

**A：** 核心思想是：**语言模型预测得越准，压缩得就越好。** 这两件事本质上是同一件事的两个侧面。

**压缩的本质是"消除不确定性"**。一个 token 越可预测，它包含的信息量越少，需要的比特就越少。这是香农信息论的核心：信息量 = 不确定性。

**大模型训练时的损失函数**：

$$L = -\sum_{i} \log P(t_i \mid t_1, t_2, \ldots, t_{i-1})$$

最小化这个损失，就是让模型对真实 token 的预测概率尽可能高。

**与压缩的等价性**：在算术编码中，一个 token 序列的最优编码长度是：

$$\text{码长} = -\sum_{i} \log_2 P(t_i \mid \text{context})$$

**这正好就是对数似然损失的表达式！** 所以：

| 模型训练目标 | 压缩目标 |
|------------|---------|
| 最小化 $-\log P(t_i \mid \text{context})$ | 最小化编码码长 |
| 让预测概率 $P$ 尽可能大 | 让码长尽可能短 |

论文引用 Deleang 等人的工作：Chinchilla 70B（主要在文本上训练的语言模型）能把 ImageNet 图像块压缩到原大小的 43.4%，把 LibriSpeech 音频压缩到 16.4%，**超过了专门的模态压缩器** PNG（58.5%）和 FLAC（30.3%）。

**对 TokCom 的意义**：预训练大模型本身就是一个强大的语义压缩器，不需要单独训练压缩器；压缩是"免费"的；这个等价性对文本、图像、音频都成立，所以 TokCom 能统一处理多模态数据。

## Q3：压缩性能的理论边界由率-失真-感知理论定义，该理论描述码率、失真、重建信号感知质量三者之间的权衡。这句是什么意思？

**A：** 这是论文讲 TokCom 语义源压缩时提到的理论依据（参考文献 [9]，Blau et al.）。

先拆开三个概念：

- **率（Rate）**：压缩后数据的大小，如 bpp。率越低，传得越省带宽。
- **失真（Distortion）**：重建信号与原始信号的"误差"，如 PSNR、MSE。失真越小，像素层面越接近原图。
- **感知质量（Perception）**：人眼/人耳主观感受到的逼真度、自然度，如 LPIPS、CLIP score。**感知质量 ≠ 失真**——一张图可以 PSNR 很高但看起来模糊，也可以 PSNR 不高但看起来很真实。

**传统理论（率-失真，RD）**：经典香农信息论只考虑两个维度——给定允许的失真 D，最少需要多少码率 R？它假设"失真越小 = 质量越好"。

**新理论（率-失真-感知，RDP）**：Blau 等人指出，失真和感知质量不是一回事，甚至经常冲突。核心结论：

1. **三者不能同时最优**，最多同时满足两个
2. **相同码率下，追求更好的感知质量往往要以更大的失真为代价**，反之亦然
3. 存在一个**理论边界**（RDP 区域），任何压缩方案都无法突破

**直观例子**：

- 传统压缩器（JPEG、PNG）优化像素级失真，压缩太狠会变模糊、出现块效应——像素误差小，但感知质量差
- 生成式压缩（VQGAN、扩散模型）优化感知质量，可能"脑补"细节让图像逼真——感知质量高，但像素失真可能更大

**对 TokCom 的意义**：

- Tokenization 本身就是有损压缩，丢多少、丢哪些受 RDP 边界约束
- TokCom 追求超低码率 + 高感知质量，就必须在像素失真上让步
- 这解释了为什么论文实验中 TokCom 在 CLIP/LPIPS 上优于传统方案，但 PSNR 未必领先
- 评价 TokCom 要用 CLIP/LPIPS 而非只看 PSNR

## Q4：解释一下图 3(a) 是什么意思？

**A：** 图 3(a) 展示的是 **TokCom 用于语义源压缩**的两种具体做法。核心思想是：利用 GFM/MLLMs 对 token 的预测能力，大幅减少需要传输的数据量。

**左侧：无损压缩（Lossless Compression via Arithmetic Coding）**

1. 多模态信号输入（文本、图像、音频）
2. Tokenization：把原始数据切成离散 token 序列
3. GFM/MLLMs 预测 token 概率：模型根据上下文预测每个 token 的条件概率
4. 算术编码：用模型预测的概率作为先验做算术编码。预测得越准 → 概率越集中 → 编码码长越短
5. 输出压缩后的比特流（示例约 0.0011 bpp）

这一步是**无损的**，接收端能完全恢复原始 token 序列。压缩率上限由模型预测准确度决定，不需要额外训练压缩器。

**右侧：有损压缩（Token-based Lossy Compression）**

1. 同样先 Tokenization
2. 丢弃与下游任务无关的 token：如任务只是分类，背景纹理 token 可直接丢掉
3. 只在信道上传输保留下来的 token（示例 Rate 0.01 bpp / 0.1 bpp）
4. 接收端用 GFM/MLLMs 恢复：对被丢弃的 token，用模型根据上下文**预测/生成**出来

这一步是**有损的**，丢弃的 token 无法精确恢复，只能靠模型"脑补"。丢哪些、丢多少取决于下游任务和可接受的感知质量，体现了 RDP 权衡。

**左右对比**：

| 维度 | 左侧：无损压缩 | 右侧：有损压缩 |
|------|--------------|--------------|
| 是否丢失信息 | 不丢 | 主动丢弃 token |
| 压缩依据 | token 概率预测 | 下游任务相关性 |
| 接收端 | 精确恢复 | 用模型预测/生成 |
| 码率 | 较低但有限 | 可以极低（0.01 bpp） |
| 适用场景 | 需要精确传输 | 语义通信、任务导向 |

**意义**：图 3(a) 是论文四大基础 TokCom setups 中的第一个，回答"TokCom 如何利用大模型实现超低码率语义压缩"。两条路的共同点是：**压缩的智能来自预训练大模型，而不是专门训练的压缩网络。**

## Q5：图 3(a) 左边和右边有损无损的重点是不是在于是不是主动丢弃 token？

**A：** 理解基本正确，但可以再精确一点。重点确实和"是否主动丢弃 token"高度相关，但严格来说，**有损/无损的分界线在于接收端能否精确恢复原始 token 序列**，而"主动丢弃"是造成有损的**主要手段**，不是定义本身。

| | 无损（左侧） | 有损（右侧） |
|---|---|---|
| 定义 | 接收端能**精确恢复**原始 token 序列 | 接收端**无法精确恢复**，只能近似/生成 |
| 手段 | 算术编码，不丢任何 token | 主动丢弃与任务无关的 token |
| 信息论视角 | 编码可逆 | 编码不可逆，信息被永久丢弃 |

- **"主动丢弃 token" → 一定是有损**
- **"不主动丢弃" → 不一定无损**（量化、编码过程本身可能不可逆）

但在这张图里，左右对比的核心差异确实就是"丢不丢 token"。另外要注意：论文提到 **Tokenization 本身就是一种有损压缩**，所以图 3(a) 讨论的"无损/有损"是**在 token 层面**而言的。

更准确的说法：**图 3(a) 左右的核心区别，在于是否在 token 层面主动丢弃信息。左边不丢，接收端能精确恢复；右边主动丢弃，接收端只能靠大模型预测补全。**

## Q6：语义信道编码那段文字是什么意思？

**A：** 这段讲的是 **TokCom 的语义信道编码**，对应图 3(b)。核心思想：**利用 token 之间的语义相似性来设计信道编码和调制映射，让"语义相近的 token"更容易在传输中混淆，从而提升抗噪能力。**

**背景：传统信道编码只看"信道质量"**

现有无线网络中，MCS 的选取只看信道质量指示（CQI）：信道好 → 高阶调制高速率编码；信道差 → 低阶调制低速率编码。它**完全不关心你传的内容是什么**。

**TokCom 的做法：MCS 同时看"信道质量 + token 可预测性"**

- 用 GFM/MLLMs 做 token 级上下文处理，得到 token 条件概率
- 同时用传统 LLR 计算，结合信道信息
- 两者结合 → 决定该 token 用什么调制编码方案

**直觉**：容易预测的 token（如"今天天气很___"的"好"）对信道错误容忍度高，可用更省资源的编码；难以预测的 token 需要更强保护。

**关键创新：语义相似的 token 映射到"容易混淆"的星座点**

论文例子："King" 和 "Queen" 语义非常相似。如果信道噪声导致接收端把 "King" 错判成 "Queen"，从语义上看损失很小，接收端还能用 GFM/MLLMs 根据上下文推断纠正回来。

所以论文提出：**语义相似的 token 应映射到信道传输中更容易被混淆的星座点上**；语义差异大的 token 应映射到相距很远的星座点。

**怎么衡量语义相似性**：用多模态嵌入技术，每个 token 在嵌入空间是一个向量，两个 token 的语义相似性 = 它们在嵌入空间中的距离（图 3(b) 用余弦相似度）。距离近 → 映射到易混淆星座点；距离远 → 映射到不易混淆星座点。

**两种上下文处理方式的取舍**：

| 方式 | 特点 |
|------|------|
| 自回归上下文处理（next token prediction） | 减少内容缓冲延迟 |
| 双向上下文处理（masked token prediction） | 降低计算复杂度 |

**除了 MCS 还能优化什么**：发射功率和其他通信资源也可以根据 token 可预测性优化——可预测性高的 token 少分配资源，低的多分配。

**与 DeepJSCC 对比**：

| | DeepJSCC | TokCom 语义信道编码 |
|---|---|---|
| 编码依据 | 端到端训练学出来的 | token 可预测性 + 信道质量 |
| 语义相似性 | 隐含在神经网络里 | 显式利用嵌入空间距离 |
| 错误容忍 | 靠网络鲁棒性 | 靠语义相似映射 + 接收端预测纠错 |
| 是否需要训练 | 需要 | 复用预训练模型，无需端到端训练 |

## Q7：什么是信道编码以及 MCS？

**A：**

### 信道编码（Channel Coding）

**是什么**：给原始数据**加冗余**，让接收端在信道出错时还能恢复原始数据。

**为什么需要**：信道不完美——噪声、衰落、干扰会让比特翻转。如果不加保护，接收端收到什么就是什么，错了也不知道。

**直观例子**：传 1 个比特 `1`：

- 不编码：直接发 `1`，噪声变成 `0`，接收端收到 `0`，错了且不知道
- 重复编码：发 `111`，噪声最多翻转 1 位，接收端收到 `101`，按"多数投票"判定为 `1`，正确恢复

代价是效率降低，但可靠性提高。**本质：用冗余换可靠性。**

**常见信道编码**：

| 类型 | 例子 | 特点 |
|------|------|------|
| 分组码 | 汉明码、BCH、LDPC | 按块编码，块内加冗余 |
| 卷积码 | 论文案例用的 rate-1/2 卷积码 | 输出与当前及之前输入相关 |
| 纠删码 | Reed-Solomon | 抗突发丢包 |
| 现代码 | Polar 码、LDPC | 5G 标准采用 |

**编码率** = 信息比特数 / 总传输比特数。rate-1/2 表示一半信息一半冗余。编码率越低 → 冗余越多 → 抗噪越强，但吞吐越低。

### MCS（Modulation and Coding Scheme）

**是什么**：**调制方式 + 信道编码率**的组合方案，是无线通信里决定"这一段数据怎么传"的核心参数。

**1. 调制（Modulation）——每个符号携带多少比特**

| 调制方式 | 每符号比特数 | 特点 |
|---------|------------|------|
| BPSK | 1 | 最抗噪，速率最低 |
| QPSK | 2 | 较抗噪 |
| 16-QAM | 4 | 论文案例用的 |
| 64-QAM | 6 | 速率高，易出错 |
| 256-QAM | 8 | 速率最高，最脆弱 |

调制阶数越高，每符号携带比特越多，但星座点越密集，噪声一来就容易判错。

**2. 编码率——多少比特用于纠错冗余**：低编码率冗余多抗噪强，高编码率冗余少吞吐高。

**MCS 索引**：实际系统把各种"调制 + 编码率"组合排成表，用 MCS 索引来选。比如 MCS 0（QPSK 1/2，信道极差）到 MCS 27（64-QAM 5/6，信道很好）。

**传统怎么选 MCS**：只看 CQI——信道好用高阶调制+高编码率，信道差用低阶调制+低编码率。**不关心传的内容。**

### TokCom 对 MCS 的改造

| | 传统 | TokCom |
|---|---|---|
| 选 MCS 的依据 | 只看信道质量（CQI） | 信道质量 + token 可预测性 |
| 粒度 | 整个数据流统一 | 逐 token 或逐 token 块 |
| 语义信息 | 不利用 | 用 GFM/MLLMs 估计 token 概率 |
| 资源分配 | 所有比特同等对待 | 可预测的 token 少给资源，难预测的多给 |

**直觉**：容易预测的 token 即使传错也能靠上下文猜出来 → 不用花太多资源保护；难预测的 token 传错就完蛋 → 需要更强编码保护。论文还提到发射功率等资源也可按 token 可预测性优化。

**两者关系一张图**：

```text
原始数据
   ↓
信道编码（加冗余，抗错误）← 编码率决定冗余多少
   ↓
调制（映射到星座点）← 调制阶数决定每符号带几比特
   ↓
信道（噪声、衰落、干扰）
   ↓
解调 + 信道解码（纠错、恢复）
   ↓
原始数据
```

**MCS = 信道编码率 + 调制方式的组合**，是收发两端约定好的"传输档位"。

## 核心概念速查表

| 概念 | 一句话解释 |
|------|-----------|
| DeepJSCC | 端到端训练的语义通信"专家"，任务专用，可扩展性弱 |
| TokCom | 复用预训练大模型的"通才"，以 token 为通信单元，无需端到端训练 |
| 信道 | 信号从发送端到接收端经过的物理媒介或逻辑通路 |
| 对数似然损失 ↔ 压缩 | 模型预测越准，最优编码码长越短，二者数学等价 |
| 率-失真-感知（RDP） | 码率、失真、感知质量三者不可兼得，存在理论边界 |
| GFM | 能生成内容的通用大模型 |
| MLLMs | 能跨模态理解与生成的大模型 |
| 语义源压缩 | 用大模型预测 token 概率做算术编码（无损）或丢弃无关 token（有损） |
| 语义信道编码 | 按 token 可预测性选 MCS，语义相似 token 映射到易混淆星座点 |
| 信道编码 | 加冗余换可靠性，用编码率衡量冗余比例 |
| MCS | 调制方式 + 编码率的组合档位，决定数据怎么传 |
