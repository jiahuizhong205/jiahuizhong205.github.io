vLLM 是一套大语言模型推理服务系统。要理解它，首先要知道模型怎样逐 token 生成文本，其次要理解 Transformer 的自注意力为什么会产生 KV Cache，最后再看 vLLM 如何管理这部分不断增长的显存。

本文只围绕三个问题展开：

1. 一次完整的 LLM 推理如何进行；
2. 自注意力中的 Q、K、V 到底在计算什么；
3. vLLM 为什么能提高推理服务的吞吐量。

## 一、整体的推理流程

### 1. 从文本到下一个 token

对 decoder-only 大语言模型，一次生成可以简化为下面的流程：

```text
输入文本
  ↓ tokenizer
token IDs
  ↓ embedding + 位置信息
向量序列
  ↓ 多层 Transformer
最后一个位置的隐藏状态
  ↓ LM Head + softmax
下一个 token 的概率分布
  ↓ sampling / greedy decoding
选出一个新 token，并继续下一轮
```

模型一次并不会直接生成整段回答，而是不断预测下一个 token。新生成的 token 会接到原序列末尾，再作为下一轮推理的输入，直到生成 EOS 或达到长度限制。

![LLM 按 token 自回归生成](/assets/img/posts/2026-10-10-vllm/01-autoregressive-generation.png)

_图 1：自回归生成每轮产生一个新 token，并将它加入下一轮输入。图源：配套汇报 PPT。_

### 2. Prefill 阶段

假设 prompt 被分成：

```text
[Artificial] [Intelligence] [is]
```

Prefill 会一次处理 prompt 中的全部 token。虽然 decoder 使用因果掩码，每个位置只能读取自己及之前的位置，但这些位置仍然可以在同一层中并行计算。

Prefill 的主要工作是：

- 计算 prompt 中所有 token 的隐藏状态；
- 在每个 Transformer 层中完成自注意力计算；
- 计算并保存每个 token 的 Key 和 Value，建立 KV Cache；
- 根据最后一个位置的输出预测第一个新 token。

Prefill 一次处理的 token 较多，矩阵计算规模较大，通常具有较高的 GPU 并行度。

### 3. Decode 阶段

假设模型在 prefill 后生成了 `[the]`。下一轮只需要处理这个新 token，而不用重新计算 prompt 中所有 token 的 Key 和 Value。

在每一层中，decode 会：

1. 为新 token 计算 Query、Key 和 Value；
2. 将新 Key、Value 追加到这一层的 KV Cache；
3. 用新 Query 查询当前缓存中的全部 Key；
4. 根据注意力权重汇总缓存中的 Value；
5. 经过后续网络，预测再下一个 token。

标准自回归 decode 每轮通常为每条活跃序列生成一个 token。随着上下文变长，每轮需要读取的 KV Cache 也会越来越大，因此 decode 往往更容易受到显存带宽影响。

简单来说：

> Prefill 负责理解整段 prompt 并建立缓存；Decode 负责复用缓存，逐 token 地继续生成。

## 二、重点理解自注意力机制

vLLM 论文在介绍 Transformer 背景时，直接以第 $i$ 个 token 为单位定义了自注意力。设某一层的输入隐藏状态为 $(x_1,\ldots,x_n)\in\mathbb{R}^{n\times d}$，首先计算该位置的 Query、Key 和 Value：

$$
q_i=W_qx_i,\qquad k_i=W_kx_i,\qquad v_i=W_vx_i
$$

然后计算位置 $i$ 对位置 $j$ 的注意力权重，以及位置 $i$ 的最终注意力输出：

$$
a_{ij}
=\frac{\exp\left(q_i^\top k_j/\sqrt d\right)}
{\sum_{t=1}^{i}\exp\left(q_i^\top k_t/\sqrt d\right)},
\qquad 1\le j\le i
$$

$$
o_i=\sum_{j=1}^{i}a_{ij}v_j
$$

这正是 vLLM 论文中的公式（2）和公式（3）。它描述的是因果自注意力：第 $i$ 个 token 只能使用第 1 到第 $i$ 个位置的信息。下面的内容都围绕这组公式展开。

### 1. Embedding：先把 token 变成向量

神经网络不能直接处理文字。tokenizer 先把文本转换成 token ID，embedding 层再把每个 token ID 映射成一个高维向量。

![Embedding 将词映射为向量](/assets/img/posts/2026-10-10-vllm/02-embedding-words-to-vectors.png)

_图 2：Embedding 将离散的词或 token 映射到连续向量空间。_

这些初始向量可以表示词语之间的语义关系，但它们还没有充分结合当前句子的上下文。例如 `king` 的初始 embedding 是固定的，而它在不同句子中应当表达不同的上下文含义。

Transformer 的任务就是让每个 token 的表示不断吸收上下文信息。

![同一个词结合上下文后得到新的表示](/assets/img/posts/2026-10-10-vllm/03-contextual-representation.png)

_图 3：词向量结合句子中的其他信息后，逐渐变成上下文化表示。_

### 2. x_i、Wq、Wk、Wv 是什么

$x_i$ 表示第 $i$ 个 token 进入当前 Transformer 层时的隐藏状态。第一层的 $x_i$ 来自 token embedding 和位置信息；在更深的层中，它来自上一层的输出，已经融合了一部分上下文。

$W_q$、$W_k$、$W_v$ 是模型训练得到的三组参数矩阵。训练结束后，权重在推理期间保持不变；随着 token、位置、上下文和层数变化，输入 $x_i$ 以及由它计算出的 $q_i$、$k_i$、$v_i$ 会发生变化。

论文采用列向量写法，所以公式写成 $W_qx_i$。工程实现也常把多个 token 堆成矩阵后一次完成投影，本质仍然是对每个位置执行同样的三种线性变换。

可以把三者直观理解为：

- Query：当前 token 想查询什么；
- Key：每个 token 用什么特征接受匹配；
- Value：匹配成功后，这个 token 实际提供什么信息。

K 不是人工编写的关键词，V 也不是原始文本。它们都是模型在当前层学习出来的向量表示。

### 3. Query 和 Key 决定“关注谁”

对当前第 $i$ 个 token，先计算它的 Query 与某个历史 Key 的缩放点积分数：

$$
s_{ij}=\frac{q_i^\top k_j}{\sqrt d},\qquad 1\le j\le i
$$

点积越大，表示 $q_i$ 与 $k_j$ 越匹配。除以 $\sqrt d$ 可以避免向量维度较大时点积绝对值过大，使后面的 softmax 过早饱和。

接着对位置 1 到 $i$ 的全部分数做 softmax：

$$
a_{ij}=\frac{\exp(s_{ij})}{\sum_{t=1}^{i}\exp(s_{it})}
$$

$a_{ij}$ 就是位置 $i$ 分配给位置 $j$ 的注意力权重，并且 $\sum_{j=1}^{i}a_{ij}=1$。对整个序列同时计算时，这些点积会组成注意力分数矩阵；图中每一列对应一个 Query 与各个 Key 的匹配结果。

![Query 与 Key 的点积形成注意力分数矩阵](/assets/img/posts/2026-10-10-vllm/04-query-key-scores.png)

_图 4：每个 token 生成自己的 Query 和 Key，二者的点积决定 token 之间的相关程度。_

公式中的求和上限是 $i$，这已经表达了 causal mask 的作用。例如计算第 5 个 token 时，只对第 1 到第 5 个位置归一化，不允许读取尚未生成的第 6 个 token。实际矩阵实现通常通过把未来位置的分数设为负无穷来达到同样效果。

### 4. Value 决定“取回什么”

Query 与 Key 得到权重后，模型使用这些权重对 Value 做加权求和：

$$
o_i=\sum_{j=1}^{i}a_{ij}v_j
$$

$a_{ij}$ 越大，$v_j$ 对输出 $o_i$ 的贡献就越大。$o_i$ 因而汇总了当前位置认为重要的历史信息，随后会经过输出投影、残差连接和后续网络。

![注意力权重对 Value 加权求和](/assets/img/posts/2026-10-10-vllm/05-value-weighted-sum.png)

_图 5：注意力权重与 Value 相乘并求和，得到上下文增量，再通过残差连接更新 token 表示。_

因此可以把一次自注意力总结为：

> Q 和 K 决定从哪些位置取信息，V 决定真正取回的信息内容。

上面的公式描述单个 attention head。Transformer 会并行使用多个 head；不同 head 拥有各自的 $W_q$、$W_k$、$W_v$，分别在不同表示子空间中计算这套公式，最后再合并输出。

### 5. 自注意力为什么会产生 KV Cache

在因果注意力中，历史 token 不能看到未来。因此，对同一次请求、同一层和同一位置而言，历史 token 已经计算出的 Key 和 Value 不会因为后续生成而改变。

如果每生成一个新 token 都重新计算全部历史 K/V，会产生大量重复计算。所以推理系统把每一层的历史 K/V 保存下来：

```text
Layer 1: K1...Kt, V1...Vt
Layer 2: K1...Kt, V1...Vt
...
Layer N: K1...Kt, V1...Vt
```

下一轮只计算新 token 的 Query、Key 和 Value，然后让新 Query 查询缓存中的全部 Key，并汇总对应 Value。

这里通常不缓存历史 Query，因为它们已经完成了各自位置上的查询；未来仍会被新 Query 使用的是历史 Key 和 Value。

需要注意，K/V 只在特定模型、特定层、特定位置和特定上下文中固定。相同 token 出现在不同位置或不同上下文中，得到的 K/V 可能不同。

## 三、简单理解 vLLM 的原理

### 1. KV Cache 带来了新的显存问题

KV Cache 避免了重复计算，但它有两个特点：

- 每个请求都有自己的 KV Cache；
- 每生成一个 token，所有 Transformer 层都要追加新的 K/V。

服务系统事先不知道一个请求最终会生成多少 token。如果按最大长度为每个请求预留一整段连续显存，就会出现大量当前未使用的预留空间、请求提前结束产生的内部碎片，以及不同大小空闲区形成的外部碎片。

![连续分配 KV Cache 带来的内存浪费](/assets/img/posts/2026-10-10-vllm/06-kv-cache-fragmentation.png)

_图 6：按最大长度连续预留 KV Cache 时，会产生预留空间和内外部碎片。图源：配套汇报 PPT。_

显存浪费会减少 GPU 能同时容纳的请求数。batch 变小后，GPU 的并行能力也难以充分利用。

### 2. PagedAttention：按 block 管理 KV Cache

vLLM 的核心思想来自操作系统的分页机制：逻辑地址连续，不代表物理内存必须连续。

它把一条序列的 KV Cache 切成固定大小的 logical KV blocks，并在需要时为它们分配 physical KV blocks。block table 负责记录二者的映射关系。

![逻辑 KV block 到物理 KV block 的映射](/assets/img/posts/2026-10-10-vllm/07-logical-to-physical-kv-blocks.png)

_图 7：逻辑上连续的 token 可以保存在不连续的 GPU 物理 block 中。图源：配套汇报 PPT。_

生成过程中：

1. prefill 结束后，系统只为已有 prompt 分配必要的 blocks；
2. decode 产生的新 K/V 先写入最后一个 block；
3. 最后一个 block 写满后，再申请新的物理 block；
4. attention 计算通过 block table 找到所有历史 K/V；
5. 请求完成后，其物理 blocks 可以立即交给其他请求使用。

这样不需要提前为最大输出长度预留连续显存。固定大小 block 也基本消除了外部碎片，内部浪费通常只存在于序列最后一个未填满的 block。

### 3. vLLM 为什么能提高吞吐量

vLLM 并没有改变 Transformer 的注意力公式，也不会为了提速修改模型应当生成的结果。它主要优化推理服务的资源组织方式：

```text
更高效地管理 KV Cache
        ↓
同一块显存容纳更多活跃序列
        ↓
调度器可以组织更大的动态 batch
        ↓
提高 GPU 利用率和整体吞吐量
```

除了 PagedAttention，vLLM 还使用迭代级调度。某个请求完成后，新请求可以在后续 decode 迭代中加入，而不需要等待原来整批请求全部结束。这通常称为 continuous batching。

所以，理解 vLLM 可以抓住一句话：

> Transformer 解决“每个 token 如何根据上下文计算”，KV Cache 避免重复计算，而 vLLM 解决“许多请求的 KV Cache 如何在有限显存中高效共存”。
